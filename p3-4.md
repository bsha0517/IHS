# 1. PURPOSE OF P3.4

P3.4 is:

# NURSING / VITALS / PRE-CONSULTATION WORKFLOW

This is NOT another whole-system audit.

Do NOT redesign the clinical architecture.

Do NOT rebuild:

* Patient
* Appointment
* Episode
* Encounter
* VitalSign
* Diagnosis
* Prescription
* ClinicalOrder
* Doctor encounter workflow
* Queue infrastructure

These capabilities already exist.

The objective is:

> Make the nursing/pre-consultation workflow coherent from patient check-in through vitals/pre-consultation assessment and safe handoff to the doctor.

The intended conceptual flow is:

Reception
→ Patient Checked In
→ Optional Nursing / Pre-Consultation
→ Vitals / Basic Assessment
→ Ready for Doctor
→ Doctor Consultation

However:

> Nursing/triage MUST NOT become a mandatory step for every clinic.

Some clinics may use:

Check-in
→ Waiting
→ Doctor

Others may use:

Check-in
→ Nursing
→ Ready for Doctor
→ Doctor

P3.4 must preserve both operational models wherever possible without introducing a large workflow engine.

# 4. NURSING WORKFLOW PRINCIPLE

A nurse should quickly understand:

1. Which patients require nursing/pre-consultation?
2. Who has been waiting longest?
3. Why is the patient here?
4. Have vitals already been recorded?
5. Are there important alerts?
6. What basic pre-consultation information needs capture?
7. Is the patient ready for the doctor?

The workflow should minimize repeated patient searching.

# 8. ENCOUNTER CREATION AND NURSING

Inspect whether nursing currently requires an Encounter to record vitals.

If VitalSign is encounter-scoped, determine the safest workflow.

Potential options:

* encounter is created before nursing
* nurse starts/opens encounter
* doctor starts encounter after nursing and reuses existing encounter

Do NOT allow Nurse + Doctor to accidentally create duplicate encounters.

Preserve P3.3's unique `Encounter.appointmentId` guard and idempotent start behavior.

If Nurse creates the encounter first:

Doctor must see:

"Open Encounter"

not create a second one.

Do not change provider ownership semantics casually.

If the encounter currently represents the physician consultation specifically rather than the broader visit, do not misuse it without examining the model first.
