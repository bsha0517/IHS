# 1. PURPOSE

P3.13 is:

# CROSS-ROLE END-TO-END WORKFLOW VERIFICATION

This is NOT another feature-development phase.

This is NOT another whole-system audit.

This is NOT a request to redesign workflows.

The objective is:

> Prove that the HIS can support realistic clinic operations across multiple departments, users, permissions, branches, clinical records, inventory, billing, accounting, HR, and notifications without relying on Super Admin to perform ordinary operational work.

The central question is:

> Can a real clinic operate from opening to closing using the HIS, with each employee performing only their own job while the same records move correctly between departments?

# 2. PRIMARY METHOD

For P3.13:

1. Trace the existing workflow.
2. Create realistic controlled fixtures.
3. Login/use the actual operational role.
4. Perform the workflow.
5. Switch to the next role.
6. Continue using the SAME underlying patient/order/invoice/etc.
7. Verify resulting records directly.
8. Verify permissions.
9. Verify accounting/inventory consequences.
10. Fix only defects that actually break or corrupt the tested workflow.
11. Re-run the affected workflow.
12. Run the complete regression suite.
13. Stop.

Do NOT start with another architecture review.

## BLOCKER

Workflow cannot complete.

* legitimate role lacks required access
* record handoff broken
* cross-module reference lost
* accounting corrupt
* stock corrupt
* cross-branch leak
* privilege escalation
* patient clinical record corruption

Fix immediately.

## HIGH

Workflow completes but produces materially incorrect state.

Fix before closing P3.

## MEDIUM

Workflow completes safely but UX is confusing or inefficient.

Fix only if narrow and clearly P3.13-related; otherwise backlog.

## LOW

Polish/convenience.

Backlog.
