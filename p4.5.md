# 1. PURPOSE

P4.5 is:

# PERFORMANCE / CONCURRENCY / LOAD VALIDATION

The objective is:

> Measure the performance and concurrency limits of the current HIS, identify real bottlenecks, fix only demonstrated high-impact issues, and establish an evidence-based capacity recommendation for commercial deployment.

This is NOT:

* speculative optimization
* architecture redesign
* Redis introduction by default
* read replicas by default
* Kafka
* microservices
* CDN redesign
* premature caching
* database sharding
* regulatory work

# 66. PERFORMANCE FIX SEVERITY

## BLOCKER

Examples:

* normal workload corrupts data
* deadlocks in ordinary workflow
* DB pool exhaustion under modest load
* 50 concurrent users make system unusable
* Outbox never recovers
* stock/accounting invariants fail

## HIGH

* key workflow p95 far above acceptable target at expected load
* major query/lock bottleneck
* severe connection pressure

## MEDIUM

* slower edge workflow
* optimization helpful but not go-live blocker

## LOW

* cosmetic optimization

Fix BLOCKER/HIGH where reasonable.

Do not chase LOW issues.
