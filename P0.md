2. P0-01 — BRANCH DATA ISOLATION

The audit found that branch isolation is not consistently enforced server-side for read operations.

This is a critical healthcare privacy/security issue.

Examples identified include:

* listInvoices
* getInvoice
* listAppointments
* getPatient

and potentially other list/get functions.

Do NOT fix only these four functions.

Perform a systematic audit of every read path involving branch-owned information.

Search:

* Patient
* Appointment
* Encounter
* Clinical data
* Invoice
* Payment
* Inventory
* Procurement
* Assets
* HR
* Reports
* Laboratory
* Pharmacy
* Radiology

Determine the effective branches from the authenticated session.

Do not trust:

branchId

coming from:

* query string
* route parameter
* form
* client component
* API request

as proof that the user may access that branch.

The server must independently verify branch access.

⸻

3. CENTRALIZE BRANCH AUTHORIZATION

Avoid fixing branch authorization with dozens of unrelated custom conditions.

Create or improve a centralized mechanism such as:

getAuthorizedBranchScope(session)

or equivalent.

It should determine:

* Organization
* Allowed branches
* All-branch privilege if applicable

Then domain queries should automatically restrict data.

Conceptually:

WHERE organizationId = session.organizationId

AND branchId IN session.authorizedBranchIds

unless the role genuinely has organization-wide branch access.

7. P0-02 — OUTBOX RELIABILITY

The audit found a serious event-processing defect.

Failed outbox events become:

failed

but the dispatcher only retrieves:

pending

Therefore failures may never retry.

This can create situations such as:

Invoice issued successfully

BUT

Accounting journal not created.

That is unacceptable.

Fix the event reliability architecture.

⸻

8. OUTBOX STATE MACHINE

Design explicit states such as:

PENDING

PROCESSING

COMPLETED

FAILED

DEAD_LETTER

or equivalent appropriate to the existing architecture.

Store:

* Attempt count
* Last attempt
* Next retry
* Last error
* Completed time

Implement controlled retry.

Example strategy:

Attempt 1

→ short delay

Attempt 2

→ longer delay

Attempt 3

→ longer delay

…

After configured maximum attempts:

→ DEAD_LETTER

Do not create infinite aggressive retry loops.

13. P0-03 — EXPIRED STOCK / FEFO

The audit found that expired inventory can currently be selected first because FEFO sorts by earliest expiry without excluding already-expired stock.

Fix this immediately.

Available batches must normally satisfy:

quantity > 0

AND

expiryDate IS NULL OR expiryDate >= allowedDate

according to defined expiration semantics.

Do not simply reorder expired stock.

Exclude it.

⸻

14. FEFO SAFETY

The operation should fail with a meaningful error rather than consuming expired stock.
