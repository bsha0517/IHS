# 1. PURPOSE

P3.12 is:

# ADMIN / SETTINGS / ROLE-AWARE NAVIGATION

This is NOT a whole-project audit.

The objective is:

> Make the HIS administratively operable and role-aware: organization settings, branches, users, roles, permissions, master/configuration data, access assignments, navigation visibility, and default landing behavior should be coherent, safe, and understandable.

This phase should answer:

* How does an Admin configure the organization?
* How are branches managed?
* How are users created and granted access?
* How are roles/permissions understood?
* Which modules should each role see?
* Where should each role land after login?
* Can users see or navigate to modules they cannot actually use?
* Are important configuration surfaces accessible without exposing unrelated sensitive settings?

Do NOT build new clinical, billing, inventory, finance, HR, or notification workflows here.
