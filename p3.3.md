→ Open Patient
→ Start/Open Encounter
→ Review Patient 360

# 5. DOCTOR WORKSPACE PRINCIPLE

A doctor should not have to jump between many unrelated screens to complete one consultation.

The encounter should function as the clinical workspace.

It should answer:

1. Who is the patient?
2. Why are they here?
3. What important history/alerts should I know?
4. What happened before?
5. What are today's observations?
6. What is my assessment?
7. What actions/orders/prescriptions are needed?
8. What follow-up is required?
9. Is the encounter complete?

# 7. APPOINTMENT → ENCOUNTER

This is a critical workflow transition.

Inspect how a doctor currently starts an encounter from a waiting appointment.

Desired behavior:

Waiting appointment
→ Doctor chooses patient
→ Existing encounter is opened if already created
OR
→ New encounter is created using the existing domain function
→ Appointment/encounter relationship preserved
→ Doctor lands directly in encounter workspace

Avoid forcing the doctor to:

* search the patient again
* navigate to Patient 360
* separately create an encounter
* return to another page

unless required by existing architecture.

Do NOT create duplicate encounters accidentally.

The workflow should be idempotent enough that double-clicking or reopening does not create multiple active encounters for the same intended consultation.

If there is already a uniqueness/state guard, preserve it.

If a genuine duplicate-encounter race exists directly in this workflow, fix only that narrowly.
